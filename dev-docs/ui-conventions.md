# UI conventions (follow these when adding fields)

Moved out of CLAUDE.md to keep that file short. Read the bullet for the area you are touching.

- **Bindings:** `<input data-bind="path.in.char">` binds two-way through a global listener in `app.js`.
  - Add `data-type="num"` for numbers and `data-rerender` to redraw the page on change.
  - In `sheet.js`, use the helpers `inp(path, opts)`, `chk(path)` and `sel(path, options)`.
- **Computed values:** `<span data-calc="path.in.derived" data-fmt="sign|plain|slots">` is filled from `compute()` after every change. Use `calc(key, fmt)` in `sheet.js`.
- **Rules links:** `data-entry="Name"` (optional `data-cat`, `data-entry-id`) makes any element open that compendium entry in the side drawer. Use `ref()` / `refId()`.
- **Saving:** after mutating `state.char` in code, call `changed()`, or `changed({ rerender: true })` if the layout changes. Saving is debounced and automatic.
- **Bonuses:** go through `stack()` with a bonus type so the stacking rules apply. Buffs and conditions are `{target, value, type, scale?}` effects. `value` may be a formula using `bab`, `lvl`, `floor`, `ceil`, `min` or `max`. Valid targets are in `MOD_TARGETS`.
- **Save-format changes:** adding a field means giving it a default in `newCharacter()`; `migrate()` back-fills old saves automatically. Renaming or reshaping a field needs explicit code in `migrate()`. Never break old save files.
- **Escaping:** use `esc()` for anything user- or data-supplied that goes into HTML.
- **Text fields:** names and notes use `textField()` (`tf()` in `sheet.js`), which shows readable text. Double-click edits it; single click opens the full text in the drawer when `read` is set. Numeric fields stay as normal inputs. Use `showCustom({name, cat, html})` to put non-compendium content in the drawer.
- **Tooltips:** `title="..."` attributes are shown by our own styled tooltip (`initTooltips` in `ui.js`), which moves the text into `data-tip`. Use `title` as usual; no extra work.
- **Sheet search:** `searchindex.js` (pure, tested) indexes the open character; `sheetsearch.js` is the top-bar UI. A new character field worth finding goes into `buildIndex`.
- **Text selection:** the desktop window (pywebview) disables text selection app-wide. Anything the user may want to copy (stat blocks, entry text) must opt in with `user-select: text` in `app.css`.
- **Class resources:** `resources.js` (pure, tested) lists the pools a character's classes give (arcane reservoir, rage rounds, ki, grit...). Current points live in `c.resources[id]` (absent = start of day); `c.trackers` are the player's own counters. `views/resources.js` draws them on Overview, and the arcanist's reservoir also appears in its spell card. To add a pool, add a line to `classResources`.
- **Level-up warnings:** `levelcheck.js` (pure, tested) lists what is left undone when a level is applied; `warnBox()` in `ui.js` shows it with "Go back and fix" / "Apply anyway".
- **Down vs. dead:** the Overview HP card and summon cards use an amber frame when down (0 or below) and a red, greyed frame once HP reaches minus the Con score. Summons store `con`.
- **Pictures:** `cropper.js` is the picture chooser with a drag-to-recenter and zoom window (`imagecrop.js` holds the tested crop maths). `picFrame()`/`picAction()` give companions (large, 4:3) and summons (small square) an `image`; the uncropped original is kept in `imageSrc` (`portraitSrc`/`avatarSrc` on the character) so it can be repositioned later.
- **Companion eligibility:** `companionSources()` in `companions.js` works out familiar and animal-companion levels from classes plus chosen abilities, feats and archetypes (arcanist Familiar exploit, shaman, Animal domain, Animal Ally, Boon Companion, paladin mount...). Add new grants there.
- **Options:** `options.js` keeps app options (theme, accent, text size, compact layout, tooltips, animations, startup behaviour) in `localStorage.options`; `sanitize()` is pure and tested, `applyOptions()` sets CSS variables and `data-*` flags on `<html>`. The sidebar's Options button opens the window, which has Look, Sound, Cookie and Discord tabs (`optionRows()`; add a row to the tab it belongs to). Add a new option to `DEFAULTS`, `sanitize` and `showOptions`. Sheet tab order is `tabOrder` (saved keys, merged with the usual list by the pure `orderKeys`) and `tabDrag` turns on dragging in `wireTabDrag` (`sheet.js`); a new tab only needs adding to `TABS`.
- **Themes:** the default theme is Dusty tome; Classic dark is the palette in `:root` of `app.css` (there is no light mode). Extra themes are `html[data-theme="<name>"]` blocks in their own `css/theme-<name>.css` (Dusty tome is `theme-tome.css`), listed in `THEMES` in `options.js`. A theme overrides the same CSS variables and may restyle components; textures are SVG `feTurbulence` sources in `make_tome_css.py` baked into `web/css/tome/*` by `node tools/bake_tome_textures.mjs` (run it after changing a texture; drawn live they were re-rendered on every tile repaint). `theme-tome.css` is generated: edit `tools/make_tome_css.py` and run it. Cards cycle through four paper variants (`:nth-of-type`), each lighter in the middle and darker toward the edges. Keep it cheap to paint (a scroller whose background is not opaque, like `#main` in Dusty tome, repaints on every scroll step unless it has its own layer: that is why `#main` has `will-change: transform` in `make_tome_css.py`; the Spells and Skills tabs scrolled at about 50 ms a frame without it, 4 ms with it, measured by scrolling in headless Chrome and timing frames): no `background-blend-mode`, no `background-attachment: fixed`, no big filters at runtime (textures are baked images); never use `outline` for a card frame (a negative-offset outline made each hover/scroll step repaint the whole card, 3x the GPU raster work in the real window; the frame is `.card::before`). Measure in the real desktop window by starting `app.py` with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333` and tracing over CDP with real `Input.dispatchMouseEvent` hovers/wheels; headless Chrome and rAF timings did not show this. The tab page turn (`playPageTurn` in `options.js`) is the old page cloned (only the part on screen) into 14 overlapping hinged strips that bend, animated in CSS; going back a tab plays it in reverse with the new page as the moving sheet. Cost matters here: the animated `--c` inherits, so `.pt-clone` resets it to 0 (otherwise every element of every copy restyles each frame); busy pages get fewer strips (`pageTurnStrips`); the copies keep the card paper (dark base colour with no texture looked wrong) but drop the blurred inner shadow. Page turn is a boolean option `pageTurn` (old Full/Light/Off values are converted). Measured in headless Chrome by timing a tab switch.
- **Cookie (the mascot):** `web/js/pet/` is the rude thrush in the sidebar's `#cookie-slot`. `art.js` is his SVG (the Pet Shopper bird with the thrush skin, trimmed, plus a cigarette and brows) and `css/pet.css` his styles, all scoped under `#cookie` (the generic class names `.arm`, `.skin`... must not leak). `facts.js` (pure, tested) boils the character down to a few facts and `diffFacts` says what happened (damage, down, dead, cast, summon, item, gold...); `app.js` `changed()` calls `observe()`, which waits 650 ms for typing to stop, and `openCharacter`/`createCharacter` call `opened()`. `lines.js` is his dialogue: add lines to `LINES` (`{name} {n} {item} {spell} {summon}`; a leading `~` is his cute act, a leading `*` an action). `pet.js` decides whether he talks (Options: off, Quiet/Normal/Chatty, Bleeped swearing, squawks), picks a face and move per event (`REACT`), and plays them. The "Cookie" option cannot be turned off on purpose (`sanitize` forces it on; unchecking fires `cookie-refuse` and he laughs). His size is `--cs` on `#cookie-slot`; the bubble is positioned from it so the tail meets his beak. To react to something new, add a fact and a case in `diffFacts`, a `REACT` entry and a `LINES` key.
- **Sound effects and heal reaction:** `sfx.js` plays named effects from `web/sounds/` (level-up, heal), scaled by the Volume option (`volume()` in `options.js`, 0 to 1; 0 is silent). Each effect has a pool of sounds (`soundItems()` in `sfx.js`): the built-in files, any of which can be switched off (option `soundOff`), plus audio files the player added (up to 8 per effect, stored by the server in `%LOCALAPPDATA%Cookie's Sheetssounds` as `<effect>__<id>__<label><ext>`; `PF_SOUND_DIR` overrides; `/api/sounds`, `/api/sound`, `/api/sound/delete`, `/api/sound-file`). `playSfx` picks one at random; an empty pool is silent. Options -> Sound lists each effect with Play, remove, Add and Restore defaults (which also brings back built-in sounds that were switched off). The same slider scales the page-turn sound and Cookie's squawks, which keep their own on/off checkboxes. `healfx.js` (`hpFx`) animates any `.hp-bar` after a heal or damage (`kind: 'heal'|'hurt'`); the Overview sets `state.healFx`, companions `state.compFx` and summons a module `sumFx` just before re-rendering, and the next draw consumes it, with strength from `frac` (share of max HP). Sounds: Heal button plays `heal`, Full heal `fullHeal`, damage a random `hit`.
- **Developer tools:** anything for the author only lives in `web/dev/` (today `animlab.js`, the floating Animation lab opened from Options → Developer tools). `options.js` shows that button only when `dev/animlab.js` exists. `build_exe.ps1` builds from a copy of `web` without `dev/`, and `python tools/make_zip.py` zips `dist` for sharing and refuses if `web/dev`, `tests` or `tools` are in it. Never add dev tools anywhere else, and never put them in a shipped file.
- **Sharing:** `web/js/version.js` holds the version shown in Options (raise it for each build you share). The app writes problems to `%LOCALAPPDATA%\Cookie's Sheets\error.log` and falls back to the default browser if the native window cannot open. `tools/normalize_sounds.py` levels every file in `web/sounds/` (run it after adding a sound).
- **Name icon:** the square beside the character name in the top bar is the button for adding, changing, recentering and removing it.
- **Changelog:** add an entry at the top of `web/js/changelog.js` when a batch of changes ships; it feeds the sidebar's "What's new" window. Keep items to one short, plain sentence each.
- **Stat-block links:** `termlinks.js` (pure, tested) turns ability names in stat-block text into compendium links. Add new names to its lists.
- **Archetype targets:** `findTargets()` in `features.js` falls back to class-specific `ALIASES`, and `EXTRA_FEATURES` adds features the class table omits (weapon and armor proficiency, spellbook, patron spells). About 3% of targets still show as plain text (swashbuckler and gunslinger deed names, paladin auras).
- **Sheet tab bar:** `render()` keeps the sheet's tab bar in the page and only replaces `#tab-body` (tracked by `main.dataset.view`), so tabs never flicker. Don't add transitions or size changes to `.tab`.
- **Rolls and where numbers come from:** `roller.js` handles rolling (click any element with `data-roll`, `data-roll-weapon`, `data-roll-add` or `data-roll-dice`); `dice.js` is the pure dice logic. `compute()` fills `d.bd` (`calc.js`): for each rolled number, a list of `{label, value}` parts that add up to it (`stackParts()` lists the buffs that count, by name and bonus type). The hover text (`rolltip.js`, built live in `roller.js` `tipFor`) shows them. When you add a rolled number, add its parts to `d.bd` under the same path as its `data-roll` key; `tests/breakdown.test.mjs` checks every part list sums to its total. Companion numbers carry their own `data-tip` built in `views/companions.js` from `computeCompanion`'s `bd` and attack `parts`.
- **Spells tab:** each spell level is a flow of chips (`.sp-chip`). Clicking one shows the spell in the side panel (`openSpell` in `sheet.js`); its actions (Roll, Summon, Prepared, Cast, Delete, and name/description for custom spells) are drawn into the panel's `.entry-actions` by `renderSpellActions` when the `entry-shown` event arrives, and cleared on `drawer-closed`. Prepared casters: `prepared` is what is left to cast, `cast` what was cast since Rest. Spontaneous/arcanist casters spend slots (`used[level]`, `slotsLeft()`); prepared spells there are only a list. Roll buttons come from `fillSpellRolls` (roller.js), which only looks up the opened spell.
- **Roll modifiers:** the roll bar's Modifier chip opens a window of presets (`MOD_PRESETS` in `dice.js`; presets with the same `group` replace each other) and a custom number. `addMods` appends the total to d20 expressions only, and the roll's label lists them. Clicking a rollable number opens the roll window (`rollWindow`/`askRoll` in `roller.js`; option `rollAsk`, Shift skips it) with the same presets (`presetsFor(attack)`) plus Advantage/Disadvantage and Roll here / Send to Discord (`doRoll({..., send})`). They last for the next roll unless "Keep it until I clear it" is ticked. Add a preset with a line in `MOD_PRESETS`. The Penalties row starts folded (`penaltiesOpen`, a click on its heading shows it). The Discord switch is one class set (`discordClass()`: `dchip` + `on` / `local`), used in the roll bar and the roll window. One-roll situations (flanking, prone, dazzled, charging) live there; anything that lasts or changes AC/damage is a `BUFF_PRESETS` entry in `data.js` instead, so it is not offered in both places.
- **Notes tab:** `notes()` in `sheet.js`, with inner tabs (`NOTE_TABS`, the open one is remembered in `notesTab`). Free text (`c.story`, `c.notes` = General notes, which used to be the single Bio notes box), plus lists `c.quests`, `c.npcs`, `c.lore` and `c.sessions` (shown newest first), all added with `data-add` and removed with `data-del`, and all searchable (`searchindex.js`). The Overview has a short Notes box (`c.quickNotes`) under Offense.
- **Re-drawing:** `changed({ rerender: true })` keeps the scroll position.
